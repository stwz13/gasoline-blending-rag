# Семантический поиск по технологическому регламенту приготовления товарных бензинов

Репозиторий курсовой работы «Семантический поиск по технологическому регламенту приготовления товарных бензинов». Цель работы — прототип RAG-системы, которая по вопросу на естественном языке находит фрагменты регламента автоматизированной станции смешения бензинов (АССБ) Омского НПЗ и формирует ответ со ссылкой на источник.

Корпус — учебный аналог технологического регламента АССБ. Он составлен по открытым источникам: научно-технической литературе, выпускным работам ТПУ, публикациям об АССБ Омского НПЗ, государственным стандартам и нормативным документам.

## Разметка документов

Каждый документ начинается с YAML-шапки с полями `document`, `title`, `doc_id`, `topics` и `sources`. Поле `sources` содержит номера источников из [docs/sources.md](docs/sources.md).

Заголовок документа — `#`, разделы — `##` с номерами, подразделы — `###`.

Перед каждой таблицей и нумерованной процедурой стоит однострочный комментарий с метаданными в формате JSON для последующего чанкинга:

```markdown
<!-- chunk: {"type": "recipe", "product": "АИ-95", "components": ["риформат", "алкилат", "изомеризат"], "description": "Рецептура бензина АИ-95, % мас."} -->

Таблица 3.2 — Рецептура бензина АИ-95, % мас.

| Компонент | Доля, % мас. |
| --------- | ------------ |
```

| Поле          | Значения                                                                         |
| ------------- | -------------------------------------------------------------------------------- |
| `type`        | `text`, `recipe`, `equipment`, `norm`, `procedure`, `component`                  |
| `product`     | марка бензина: `АИ-92`, `АИ-95`, `АИ-98`, `АИ-100` и др.                         |
| `category`    | категория оборудования или темы: `резервуары`, `насосы`, `АСУ`, `присадки` и др. |
| `method`      | способ смешения: `поточное`, `циркуляционное`                                    |
| `description` | краткое текстовое описание блока                                                 |

## Чанкинг

[src/chunking.py](src/chunking.py) режет корпус на чанки. Готовые чанки — [data/chunks.jsonl](data/chunks.jsonl): 171 чанк (116 текстовых, 55 табличных), по одному JSON-объекту на строку. После правок корпуса файл пересобирается командой ниже.

```bash
pip install -r requirements.txt
python -m src.chunking --max-chars 1500 --overlap 200
```

- Документ делится по заголовкам `##`/`###` и комментариям `<!-- chunk -->`.
- Таблица — отдельный чанк с подписью; длиннее 2500 знаков делится по строкам с повтором шапки, глоссарий — по одному сокращению.
- Текст режется по абзацам, затем по предложениям: до 1500 знаков, перекрытие до 200.

| Поле                                                            | Содержание                         |
| --------------------------------------------------------------- | ---------------------------------- |
| `chunk_id`                                                      | номер документа и чанка, `03-005`  |
| `doc_id`, `document`, `doc_title`                               | документ                           |
| `section`, `subsection`, `section_path`                         | раздел                             |
| `chunk_type`                                                    | `text` или `table`                 |
| `block_type`, `category`, `method`, `components`, `description` | поля разметки                      |
| `grades`                                                        | марки бензина                      |
| `table_caption`, `part`, `parts_total`                          | подпись и часть таблицы            |
| `topics`, `sources`                                             | темы и источники документа         |
| `text`                                                          | фрагмент                           |
| `embed_text`                                                    | фрагмент с контекстом для энкодера |

## Поиск

[src/retrieval.py](src/retrieval.py) ищет по `data/chunks.jsonl` методом BM25 и векторным поиском, [src/hybrid_retrieval.py](src/hybrid_retrieval.py) объединяет их в гибрид.

```bash
python -m src.retrieval build --encoder e5                    # индекс FAISS -> data/index/e5.faiss
python -m src.retrieval search "давление нагнетания"          # BM25
python -m src.retrieval search "ДНП смеси" --mode dense      # вектор
python -m src.hybrid_retrieval "ДНП смеси" --method rrf --expand --grades АИ-95 --chunk-type table
python -m src.hybrid_retrieval "ДНП смеси" --method weighted --rerank   # с переранжированием
```

- **BM25** (`rank_bm25`) по полю `text`; слова приводятся к леммам `pymorphy3`, стоп-слова русского языка из NLTK (`nltk.corpus.stopwords`) удаляются; при первом запуске список скачивается автоматически. Из кода: `from src.retrieval import search; search(query, k=5)`.
- **Вектор**: поле `embed_text` кодируется моделью `intfloat/multilingual-e5-small` (префиксы `query:`/`passage:`) или `cointegrated/rubert-tiny2`; индекс FAISS `IndexFlatIP` по нормированным векторам сохраняется в `data/index/`.
- **Гибрид** (`src/hybrid_retrieval.py`): RRF, `1/(60 + место в BM25) + 1/(60 + место в векторном поиске)`, или взвешенная сумма `α·minmax(вектор) + (1−α)·minmax(BM25)`, по умолчанию α = 0,6 (подобрано по MRR@10).
- **Переранжирование** (`--rerank`): гибрид отбирает 20 кандидатов, кросс-энкодер `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` оценивает пары «запрос — чанк» и переставляет кандидатов по своей оценке.
- **Фильтры** `Filters(grades, chunk_types, doc_ids)`: марки бензина (хотя бы одна), типы чанков, номера документов.
- **Сокращения**: `--expand` дописывает к запросу полные формы из глоссария (документ 13), например «ДНП» → «ДНП (ДНП — Давление насыщенных паров…)».

## Оценка поиска

[data/queries.jsonl](data/queries.jsonl) — 76 запросов. 73 из них имеют ответ в корпусе и делятся на 5 категорий: факт/число, процедура, таблица, сокращения, перефраз. Для каждого такого запроса размечены фразы-доказательства (`evidence`) — точные цитаты из корпуса с ответом. Релевантным считается любой чанк, где фраза есть целиком, поэтому разметка не зависит от нарезки.

Все 25 тестовых вопросов из ТЗ входят в набор, их номер (Ф1–Ф8, П1–П5, С1–С5, Ч1–Ч4, Л1–Л3) указан в поле `tz`, привязка к разделам — в [docs/corpus_plan.md](docs/corpus_plan.md). Вопросы-ловушки Л1–Л3 (категория `trap`) не имеют ответа в корпусе, поэтому `evidence` у них пустой.

```bash
python -m src.evaluate                    # BM25, e5, гибриды, реранкер
python -m src.evaluate --reranker ""      # без переранжирования
python -m src.chunk_quality               # сравнение вариантов нарезки
```

- **Recall@5** — доля вопросов, у которых релевантный чанк попал в первые пять.
- **MRR@10** — среднее по вопросам значение 1 / место первого релевантного чанка.
- **Ловушки** — доля ловушек, которые можно отсечь порогом по оценке лучшего чанка.

## Подбор параметров и результаты

Подбор параметров с таблицами, графиками и выводами — в блокноте [notebooks/parameter_tuning.ipynb](notebooks/parameter_tuning.ipynb): нарезка корпуса, сравнение BM25 и вектора, гибрид и вес α, число кандидатов для переранжирования, раскрытие аббревиатур, итоговое сравнение.

Выбрано: 

* нарезка 1500 / 200

* α = 0,6

* 20 кандидатов для переранжирования

* раскрытие аббревиатур выключено

Лучший метод — гибрид RRF с переранжированием: Recall@5 = 0.959, MRR@10 = 0.839.

## Генерация ответа

[src/generate.py](src/generate.py) находит 5 фрагментов гибридным поиском с переранжированием и передаёт их локальной языковой модели. Модель отвечает только по фрагментам, а если ответа во фрагментах нет, отказывается отвечать. После ответа выводится список фрагментов-источников.

Модели запускаются через [Ollama](https://ollama.com): установите Ollama и скачайте модель, затем задайте вопрос.

```bash
ollama pull hf.co/yandex/YandexGPT-5-Lite-8B-instruct-GGUF
python -m src.generate "Сколько времени перемешивать бензин после закачки компонентов?"
python -m src.generate "..." --model qwen2.5:7b -k 3
```

Выбор модели — в блокноте [notebooks/generation.ipynb](notebooks/generation.ipynb): модели отвечают на перефразированные вопросы, вопросы ТЗ и ловушки, ответы сохраняются в `data/generation/answers.csv` и размечаются по шкале точности 0/1/2 и наличию галлюцинаций; для всех моделей сравнивается 3, 5 и 10 фрагментов в контексте. Выбрана YandexGPT 5 Lite 8B с 5 фрагментами: 94 % верных ответов, 88 % на перефразированных вопросах.
